# Шаг 11 — Монологи и UI-состояния

## Цель
Отделить UI внутренних монологов от обычных диалогов с персонажами.

## Зависимости
- [step-02-engine-stats-media.md](step-02-engine-stats-media.md)

## Сделать

### UI state model
- Добавить режимы отображения диалога:
  - `Dialogue` (обычный разговор);
  - `Monologue` (внутренний голос);
  - `System` (служебные сообщения/телефон).
- В данных узла предусмотреть указание UI режима.

### Визуальные отличия
- Для `Monologue`:
  - другой стиль панели (цвет/прозрачность);
  - скрытый/приглушенный speaker;
  - более спокойная анимация появления (DOTween).
- Для `Dialogue` оставить текущий стиль.

### Поведение
- Переключение между режимами должно быть автоматическим по данным узла.
- В случае отсутствия явного режима использовать fallback `Dialogue`.

### Тестирование
- Добавить 2-3 тестовых узла монолога и убедиться, что стиль реально переключается.

## Не делать
- Не переписывать всю систему UI с нуля.
- Не внедрять финальную аудио-подложку в этом шаге.

## Критерии готовности
- [ ] Для узлов монолога применяется отдельный UI-стиль.
- [ ] Для обычного диалога регрессий нет.
- [ ] Переключение режимов работает без ручных условий в UI-коде.
- [ ] Ошибок в Play Mode и Console нет.

## Unity
- Пройти сценарий с чередованием `Dialogue` и `Monologue`.
