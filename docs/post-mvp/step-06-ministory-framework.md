# Шаг 06 — Каркас мини-сюжетов

## Цель
Сделать единый технический шаблон для мини-сюжетов, чтобы подключать новые сценки без копипасты.

## Зависимости
- [step-05-chapter2-toilet.md](step-05-chapter2-toilet.md)

## Сделать

### Модель данных
- Добавить тип/метку мини-сюжета в данные узлов (например `isMiniStory` или `storySegment`).
- Поддержать единый паттерн:
  - `entryNodeId`
  - `contentNodes`
  - `exitNodeId` (обязателен).

### Рантайм поведение
- StoryEngine должен гарантировать выход из мини-сюжета:
  - если контент пустой/оборван, fallback в `exitNodeId`;
  - логировать ошибку, но не ломать прохождение.
- Сохранить флаги входа/выхода для аналитики сценария.

### Медиа
- Для мини-сюжетов поддержать `mediaSlot` (gif/video/image).
- Если ассет отсутствует, отображать безопасный placeholder.

### Инструменты
- Добавить editor helper для быстрого создания mini-story блока.
- Добавить smoke тест mini-story lifecycle: entry -> content -> exit.

## Не делать
- Не наполнять этим шагом все мини-сюжеты контентом.
- Не делать сложный cutscene timeline, если достаточно узлового сценария.

## Критерии готовности
- [ ] Есть единый технический каркас мини-сюжета.
- [ ] Мини-сюжет всегда возвращает игрока в основной поток.
- [ ] Ошибки отсутствующих медиа не приводят к soft-lock.
- [ ] Smoke тест каркаса проходит.

## Unity
- Собрать тестовый mini-story на 2-3 узла.
- Пройти Play Mode и проверить fallback.

## Промпт
```text
MaratGame: выполни только docs/post-mvp/step-06-ministory-framework.md.
Нужен общий технический каркас мини-сюжетов с гарантированным возвратом.
```
